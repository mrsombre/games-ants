# План игры про муравьёв

Статус: предварительная концепция, записана 5 сентября 2026 года. Минимальный технический каркас уже создан: React + Vite frontend и Hono Worker с единым локальным запуском. Каркас опубликован: [production](https://games-ants.warmvibes.workers.dev/). Игровые механики остаются следующими шагами.

## Концепция

Браузерная игра про управление муравейником, вдохновлённая механиками Fallout Shelter: строительство комнат, развитие поселения и экспедиции за полезными находками. Собственная тема, персонажи и оформление про муравьёв.

Игрок — ребёнок восьми лет. Основное устройство — компьютер, управление мышью.

Муравейник показан сбоку в разрезе и расширяется вниз. Игрок строит комнаты и отправляет муравьёв в рейды. Внутри муравейника муравьи действуют автономно. Матка остаётся на постоянном месте.

## Основные механики

- **Строительство:** добавление комнат по мере развития муравейника, преимущественно вниз. Типы комнат, соединение между ними и стоимость строительства ещё предстоит определить.
- **Автономная колония:** муравьи самостоятельно перемещаются и выполняют работу. Точные правила распределения задач пока открыты.
- **Рейды:** игрок выбирает муравьёв и отправляет их за пределы муравейника. Они могут вернуться с полезными находками; ресурсы — первый кандидат на награду. Длительность, риски и способ показа рейда ещё не определены.
- **Матка:** неподвижный центральный персонаж колонии. Её роль в появлении новых муравьёв и условиях поражения пока не определена.
- **Виды муравьёв:** охранники, разведчики, носильщики; список можно расширить. Виды должны немного отличаться внешне и быть различимыми в игровом масштабе. Конкретные способности предстоит выбрать.

Предлагаемый игровой цикл: построить комнату → колония осваивает её → отправить рейд → получить полезные находки → расширить муравейник. Это рабочая гипотеза для первого прототипа.

## Первый прототип

Минимальный объём для проверки основного игрового цикла:

- Одна сцена муравейника в разрезе с возможностью строить вниз.
- Матка на постоянном месте и несколько автономных муравьёв.
- Три первоначальных вида: охранники, разведчики, носильщики, с простыми визуальными отличиями.
- Минимальный набор комнат и ресурсов; состав определить до реализации.
- Отправка рейда, его завершение и выдача награды. Формат рейда выбрать до реализации.
- Простой UI: несколько счётчиков численности муравьёв и ресурсов, минимальные действия для строительства и рейдов.
- Сохранение и восстановление прогресса в браузере.

Критерий проверки: ребёнок может построить комнату, увидеть самостоятельную жизнь колонии, отправить рейд и использовать полученную награду для дальнейшего развития.

## Технический план

- Браузерный 2D-проект; нативное приложение сейчас не планируется.
- **pnpm** для инициализации проекта, зависимостей и команд разработки.
- Предварительный стек: **TypeScript + PixiJS + Vite**. PixiJS остаётся рекомендацией из [сравнения движков](./engine-comparison.md); окончательный выбор ещё не зафиксирован пользователем. Phaser остаётся альтернативой при необходимости большего числа готовых игровых систем.
- Модель колонии и её сохранение отделить от отрисовки, чтобы автономное поведение и рейды можно было проверять независимо от графики.
- **localStorage** для первоначального сохранения прогресса. Формат сохранения предусмотреть с версией.
- **Cloudflare Workers** — планируемая площадка публикации браузерной сборки. Серверная игровая логика для первого прототипа пока не требуется.
- Сохранить первоначальное пожелание: отдельная автономная сборка в **один HTML со встроенными ресурсами**, запускаемая без веб-сервера. Для неё предусмотреть экспорт и импорт сохранения, поскольку поведение localStorage на `file://` не гарантировано. Ограничения и источники записаны в [сравнении движков](./engine-comparison.md).

## Порядок следующих шагов

1. Уточнить минимальные типы комнат и ресурсов, появление новых муравьёв, различия их ролей и правила рейдов.
2. Зафиксировать движок и объём первого прототипа.
3. **Выполнено:** инициализировать проект через pnpm и настроить сборку frontend и Worker. Это инфраструктурный шаг; игровой renderer ещё не подключён.
4. Реализовать минимальный игровой цикл и сохранения.
5. Проверить управление мышью, понятность UI и восстановление прогресса.
6. **Каркас опубликован** в Cloudflare Workers. Публикация игровой версии и проверка автономного HTML остаются следующими шагами.

Этот документ фиксирует концепцию будущей игры. Сейчас реализован и опубликован только технический каркас, описанный в [руководстве по разработке](./development.md). Игровой продукт, сохранения и автономный HTML ещё не реализованы.
