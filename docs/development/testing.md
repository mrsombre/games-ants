# Проверки и тестовый аудит

Тесты проверяют наблюдаемое поведение через интерфейсы систем и полный `stepGame`.
Ожидания численных результатов задаются независимо от рабочих констант: скорость,
стоимость, период удара и время стройки не читаются из реализации для вычисления ожидаемого значения.
Общие фабрики в `test-support.ts` создают состояние, но не рассчитывают результат за тест.

## Что пересмотрено

| Группа | Решение аудита |
| --- | --- |
| Геометрия и навигация | Сохранены стены и достижимость; убран повтор проверки вертикальной стены из общей симуляции. Добавлены логическая клетка, интерполяция, разворот до/после начала ребра, встречное движение и координаты указателя. |
| Постройки | Убрана проверка буквального содержимого стартового словаря. Сохранены правила размеров/связности и реальные команды. Тест обхода через чертежи исправлен: его прежняя карта не имела заявленного обхода. |
| Бой | Сценарии разделены на чистый расчёт урона и интеграцию с движением/грузом. Проверяются стороны независимо от ролей, одновременная смерть, одна цель, матка, отсутствие разведчика и остатки времени. |
| Аукцион | Сохранены приоритеты, стоимость пути и исключительность резервов. Добавлен общий алгоритм налётчиков. Слабая проверка «Y не меньше минимального» заменена конкретной областью назначения. |
| Предметы и яйца | Проверяются право переноса, один носитель, восстановление груза, живые резервы, места хранения и сохранение таймера. Старое ожидание исчезновения еды заменено на сохраняемый предмет. |
| Выведение | Отдельные заказы проверяются по выбранной кладке, месту появления, списанию и сохранности остальных объектов. |
| Целый цикл | Детерминированные последовательности команд проверяют уникальность ID, баланс еды, соседство маршрута и отсутствие потерянных носителей. |
| UI и API | Удалён тест количества/уникальности текстов подсказок и их константы интервала. Три HTTP-теста сохранены: публичный health, JSON 404 и запрет POST различают самостоятельные условия контракта. |

Часть прежних сценариев заменена, поскольку меняется само требование: враг больше не
роль, вор не проходит матку без боя, предметы не исчезают при контакте, дробные координаты
не определяют занятость клетки. Проверки прежних исключений не сохраняются как «совместимость».

Мутации выявили слишком широкий стандартный допуск `toBeCloseTo`: лишний шаг стройки
укладывался в него. Проверки времени и прогресса используют явную точность. Граничные
значения проверяются с обеих сторон, а периоды — также шагом 0,03 секунды, который
не делит время удара и лечения без остатка.

## Проверенный результат

150 тестов frontend и 3 теста backend проходят. Команды check, type-check, test и build
завершились успешно. Мутационный прогон относится к аудиту до появления склада:
он обнаружил 97,04% вариантов при пороге 95%.
Все 46 оставшихся вариантов, включая три NoCoverage, разобраны в
[отдельном отчёте](./mutation-audit.md); исходный процент не скрывает этот остаток.

## Воспроизведение

Из корня репозитория:

```sh
mkdir -p .tmp
pnpm check
WRANGLER_LOG_PATH="$PWD/.tmp/wrangler" pnpm type-check
pnpm test
WRANGLER_LOG_PATH="$PWD/.tmp/wrangler" pnpm build
TMPDIR="$PWD/.tmp" pnpm test:mutation
```

Stryker 10 использует Vitest и покрытие `perTest`, четыре процесса и порог падения 95%.
Конфигурация находится в `stryker.config.json`. Временный проект и отчёты находятся
в корневой `.tmp`; очистка временного каталога отключена. HTML-отчёт:
`.tmp/mutation/report.html`, машинный отчёт: `.tmp/mutation/report.json`.

Мутируется вся исполняемая логика `game/*.ts`. Типы без runtime-кода не порождают мутаций.
Исключены тесты, их фабрики и `scene.ts`; отрисовка и React не входят в этот мутационный
прогон. Все виды мутаций Stryker включены: строковые, логические и граничные изменения
не скрываются общими исключениями. Настройка опирается на
[конфигурацию Stryker](https://stryker-mutator.io/docs/stryker-js/configuration/)
и [Vitest runner](https://stryker-mutator.io/docs/stryker-js/vitest-runner/).

Процент Stryker включает обнаруженные по таймауту мутации; это не то же самое, что число
мутаций, отклонённых утверждением теста. Эквивалентные варианты, численная погрешность
в пределах `EPSILON` и изменения только стоимости вычисления требуют отдельного разбора,
а не бессмысленного теста ради формального 100%.

## Дополнительная проверка

Во встроенном браузере проверены загрузка сцены, видимые квадратные клетки, постановка
и завершение коридора, списание еды при выведении, появление рабочего (счётчик 3→4).
При проверке не было ошибок браузерной консоли. Измерение производительности и его
ограничения приведены в [описании архитектуры](../system-design/architecture.md#производительность).
