# Браузерная игра про муравьёв: выбор движка

Проверено по официальной документации 5 сентября 2026 года. Ниже технические факты отделены от проектных рекомендаций. Размер сборок и скорость разных движков не измерялись.

## Сравнение

| Вариант | Что предоставляет | Когда выбрать для этой игры | Один автономный HTML |
| --- | --- | --- | --- |
| **PixiJS** | 2D-рендеринг, спрайты, графика, дерево объектов, обработка мыши и касаний; WebGL и WebGPU. | Моя рекомендация для фермы или симуляции колонии: кормление, строительство камер, наблюдение за поведением. Правила симуляции, управление состояниями игры и поиск пути проектируем отдельно. | Подходящий кандидат при сборке JavaScript и ресурсов внутрь HTML; это задача сборки, а не обещание стандартного шаблона. |
| **Phaser** | 2D игровой фреймворк: сцены, ввод, камеры, анимации, звук, таймеры, tweens и физика. | Моя рекомендация для приключения за одного муравья, уровней, препятствий и мини-игр. Для фермы также подходит, особенно если нужны эти подсистемы. | Подходящий кандидат с явным встраиванием ресурсов. API текстур принимает уже созданные изображения и данные атласов. |
| **Three.js** | 3D-библиотека с деревом сцены и отображением объектов. Руководство прямо объясняет, что физику, столкновения, ввод и поиск пути для игры нужно добавлять. | Если объёмная диорама или свободная 3D-камера являются важной частью замысла. Больше собственной игровой инфраструктуры. | Возможность следует проверять на конкретной сборке. Стандартная инструкция разработки использует сервер; все загрузчики и внешние ресурсы нужно адаптировать. |
| **Babylon.js** | 3D-движок: камеры, материалы, анимации, звук, GUI, коллизии; физика доступна через интеграцию Havok. | Если нужна полноценная 3D-игра и хочется больше готовых систем. Для первой небольшой 2D-фермы эти возможности в основном не нужны. | Потребуется учитывать загрузку моделей, текстур и дополнительных модулей, включая WASM физики при её использовании. Не самый прямой старт под это ограничение. |
| **Godot Web** | Полноценный игровой движок с редактором и экспортом в браузер. Web-экспорт использует WebAssembly и WebGL 2.0. | Если визуальный редактор и последующий выпуск на других платформах важнее формата распространения. | Стандартный экспорт создаёт HTML, JS, WASM и PCK для размещения на сервере. Под требование одного файла я бы его не выбирал. |

Источники фактов по строкам: [PixiJS Introduction](https://pixijs.com/8.x/guides/getting-started/intro), [Phaser Introduction](https://docs.phaser.io/) и [Scenes](https://docs.phaser.io/phaser/concepts/scenes), [Phaser TextureManager](https://docs.phaser.io/api-documentation/class/textures-texturemanager), [Three.js Making a Game](https://threejs.org/manual/en/game.html) и [Installation](https://threejs.org/manual/en/installation.html), [Babylon.js Specifications](https://www.babylonjs.com/specifications/), [Godot Web export](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html).

На момент проверки PixiJS документирует ветку 8.x, а текущая API-документация Phaser показывает 4.1.0. При реализации нужно фиксировать выбранную версию и брать совместимые примеры: старые статьи про Phaser 2/3 могут отличаться. [PixiJS Quick Start](https://pixijs.com/8.x/guides/getting-started/quick-start), [Phaser API](https://docs.phaser.io/api-documentation/class/textures-texturemanager).

## Ограничения одного HTML и сохранений

- **Один HTML должен быть результатом сборки.** Исходники удобно держать отдельными модулями TypeScript; собирать их вместе с движком в inline JavaScript. В итоговом файле не должно оставаться внешних импортов или запросов к соседним файлам. Загрузка ES-модулей через `file://` сталкивается с ограничениями CORS. [MDN JavaScript modules](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules).
- **Изображения, звук и шрифты встраиваются явно.** Например, `vite-plugin-singlefile` встраивает JS/CSS, но не превращает автоматически всё содержимое `public` в данные внутри HTML. Все фактические ресурсы нужно проверить в собранной игре. [README плагина](https://github.com/richardtallent/vite-plugin-singlefile).
- **`localStorage` на `file://` нельзя считать гарантированным сохранением.** Его поведение для файловых URL не определено; возможен `SecurityError`. Даже наблюдаемое разделение хранилища по отдельным файлам не является обещанием браузеров. Рекомендация: автосохранение с обработкой ошибки плюс экспорт/импорт сохранения в JSON. [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).
- **Альтернатива — статическая HTTPS-страница.** Игрок просто открывает ссылку и не запускает сервер у себя. Позже можно добавить PWA; устанавливаемая PWA требует HTTPS либо localhost и отдельной настройки. Это другой способ распространения той же браузерной игры. [MDN Making PWAs installable](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Предложение для первого проекта

Начать с **PixiJS + TypeScript**, если основной интерес — собственный муравейник. Для ребёнка восьми лет за компьютером с мышкой предлагаю 2D-ферму или песочницу с короткими целями и управлением кликами. Сделать вид сбоку в разрезе: ребёнок кладёт еду, прокладывает проход, открывает новую камеру и видит понятную реакцию колонии. Это проектная рекомендация, а не ограничение Phaser.

Первый игровой цикл: **положить еду → муравьи нашли и принесли её → появилась возможность расширить дом**. Собственную модель колонии держать отдельно от визуальных объектов и сохранять только её данные. Один HTML оставить целевым форматом сборки; проверить его через `file://` на устройстве ребёнка до наращивания контента.

Если центральный замысел — управлять одним муравьём и проходить задания, выбрать **Phaser**. Настоящее 3D стоит брать после решения, что оно даёт ребёнку в самой игре: красивый объёмный вид можно начать исследовать как отдельную диораму.
