# Аукцион

Обе стороны используют `assignTasks` с одним алгоритмом. Колония и налётчики отличаются
набором предложений, а не способом управления движением. Сначала торгуется колония,
затем налётчики; это явный порядок разрешения одновременного интереса к одному предмету.

| Задание | Приоритет | Исполнители и условие |
| --- | ---: | --- |
| Перехват противника колонией | 200 | Воин или разведчик |
| Охрана подхода к матке | 190 | Свободный рабочий колонии при набеге |
| Кража предмета | 180 | Налётчик с подходящей ролью |
| Возврат найденной еды на склад | 130 | Разведчик колонии |
| Строительство | 100 | Рабочий колонии |
| Атака налётчика | 100 | Рабочий, разведчик или воин налётчиков |
| Поход за едой | 80 | Разведчик колонии, пока на складе есть свободное место |
| Перенос яйца в гнездо | 60 | Рабочий колонии |
| Уход с карты | 10 | Налётчик, когда живых противников не осталось |
| Прогулка | 0 | Свободный подвижный юнит колонии после ожидания |

Пока в клетке есть противник, юнит не участвует в торгах. Настоящее незавершённое
задание тоже исключает его из аукциона. Прогулка допускает переназначение. Появление
набега само по себе не отменяет уже выданную работу: занятый муравей продолжает её до
завершения или контакта. Свободные рабочие получают охрану, воины и разведчики — перехват.

## Выбор победителя

Предложения включают задание, точку подхода, приоритет и необходимые резервы. Для каждого
подходящего свободного юнита строится ставка. Недостижимые точки и неподходящие роли
отбрасываются до выбора победителя.

Ставки сравниваются по убыванию приоритета. Для хранения яиц предпочтительнее более дальняя
от матки клетка; для еды предпочтений нет, побеждает ближайшая по времени пути клетка склада. Далее сравнивается время пути: оставшаяся часть текущего ребра, подход,
а для переноса ещё и доставка, делённые на индивидуальную скорость. При равенстве
побеждает меньший ID юнита, затем лексикографический порядок ключей цели. Поиск учитывает стены, а не
расстояние по прямой.

После сортировки ставки просматриваются один раз. Победа занимает юнита и необходимые
резервы. Один предмет и одну клетку назначения нельзя назначить двум исполнителям в одном
аукционе; вторая свободная клетка склада достаётся следующему носителю.
Проверка действующих заданий учитывает обе стороны. Стройка не имеет исключительного
резерва: несколько рабочих складывают вклад.

Груз может нести только подходящая роль: рабочий — яйцо, разведчик — еду. Поэтому даже
дешёвая ставка разведчика не забирает яйцо. Налётчик может зарезервировать яйцо с заказом
выведения, но отменяет выведение только при физическом подборе.

## Состояния работы

`Job` — объединение по `kind`, без полей чужих работ:

- `build`: цель чертежа и готовая клетка, с которой рабочий строит.
- `haul`: ID предмета, место доставки, фаза `pickup` или `delivery`.
- `forage`: фаза `outbound` или `away`, край карты и время отсутствия; возврат — это `haul`.
- `attack`: ID противника; путь обновляется, когда меняется клетка цели.
- `guard`, `wander`, `leave`: клетка назначения.

Исполнитель продолжает маршрут и фазы уже присуждённого задания без повторных торгов.
Если противник жив, но путь к нему отсутствует, налётчик ждёт.
Стройка заканчивается вместе с чертежом; перенос — при сдаче; перехват — при исчезновении
цели; охрана — после исчезновения противников. Устаревшее задание освобождается.

`interruptJob` освобождает задание, останавливает путь, снимает признак работы и кладёт
переносимый предмет в логическую клетку юнита. Это единый механизм для боевого контакта,
явного отказа от работы и изменения карты. Предмет после прерывания не исчезает:
следующий аукцион может назначить подходящего носителя.

Рабочие и разведчики гуляют по готовым клеткам. Воин выбирает поверхность с вероятностью 0,75;
поверхностная цель находится в `x=5…11`, `y=0`. После прибытия пауза составляет 5–30 секунд.
Новая настоящая работа прерывает и ожидание, и маршрут прогулки.
