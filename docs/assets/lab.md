# Лаборатория

Набор dev-страниц для работы с графикой отдельно от игры. `lab.html` — меню, каждый
плейграунд лежит отдельной страницей в `lab/`. Первый из них — спрайты юнитов: показывает
всех существ во всех позах одновременно, чтобы править рисунок в `packages/assets/src/creatures.ts`
и сразу видеть результат во всех состояниях, не воспроизводя их в симуляции.

## Запуск

```sh
pnpm dev
```

Открыть `http://127.0.0.1:5173/lab.html` и выбрать плейграунд.

## Файлы

| Файл | Роль |
| --- | --- |
| `apps/frontend/lab.html` | Меню: список плейграундов |
| `apps/frontend/lab/creatures.html` | Плейграунд «Спрайты юнитов»: разметка панели управления |
| `apps/frontend/src/lab/creatures.ts` | Сетка на PixiJS, контролы, цикл отрисовки |
| `apps/frontend/src/lab/lab.css` | Общие стили меню и плейграундов |
| `apps/frontend/vite.config.js` | `build.rollupOptions.input` закрепляет единственный вход |

Новый плейграунд — это `lab/<имя>.html`, скрипт `src/lab/<имя>.ts` и пункт в меню; правки
в `vite.config.js` не нужны.

## Почему её нет в production

Dev-сервер Vite отдаёт любой `.html` из корня приложения, регистрации не требуется. Сборка же
идёт от списка входных точек Rollup: если `build.rollupOptions.input` не задан, входная точка одна
— `index.html`. Ни `lab.html`, ни страницы из `lab/` в граф импортов от неё не входят, поэтому
в бандл не попадают вместе со всем `src/lab/`.

Раньше это работало по умолчанию, то есть держалось на отсутствии настройки. Теперь вход закреплён
явно, чтобы добавление второй страницы случайно не увезло лабораторию в production:

```js
// lab.html and lab/ stay out of the input list: they are served in development only.
build: { rollupOptions: { input: "index.html" } },
```

Класть `lab.html` в `public/` нельзя: оттуда всё копируется в `dist` как есть.

## Устройство плейграунда «Спрайты юнитов»

Источник рисунка — общий с игрой `drawAnt` из `@app/assets/creatures`.
Лаборатория не импортирует `game` и `render`.

Сетка строится из двух списков:

- `rows` — роль и сторона: рабочий, разведчик, воин (колония и налётчики), жук, паук, матка.
- `poses` — состояние: стоит, идёт, ранен, несёт яйцо, яблоко, гриб, гусеницу.

Для каждой ячейки создаётся `CreatureAppearance`: роль, сторона, признаки движения
и работы, доля здоровья. Груз задаётся отдельно. `drawAnt` рисует объект в локальных
координатах; положение ячейки и поворот принадлежат лаборатории. Клетки с грузом
показываются у рабочих и разведчиков. Полоска здоровья матки находится в отдельном overlay.

## Контролы

| Контрол | Что делает |
| --- | --- |
| ← | Возврат в меню |
| Пауза / Пуск | Останавливает накопление времени |
| Фаза | Ставит цикл шага на конкретный кадр; перевод ползунка включает паузу |
| Темп | Множитель скорости времени, 0-3× |
| Зум | Масштаб всей сетки, 0.5-8× |
| Курс | Четыре направления: вправо (0°), вниз (90°), влево (180°), вверх (−90°) |
| Фон | Туннель (по умолчанию, `0x796246` из `packages/render/src/colony.ts`), сцена, земля, ночь, бумага, вода; подписи сами переключаются на светлые или тёмные |
| Клетки | Границы ячеек — по ним видно, выходит ли силуэт за пределы клетки |

Направления совпадают с `heading` юнита: ноль — вправо, положительный угол — по часовой стрелке,
поскольку ось `y` на канвасе направлена вниз.

Правки в `packages/assets/src/creatures.ts` подхватываются HMR: сетка перерисовывается целиком без перезагрузки.
