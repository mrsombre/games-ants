# Растеризация и атласы

Как перевести исходную графику — SVG, процедурный `Graphics` или генерацию модели — в PNG-атлас,
который движок рисует одним вызовом. В игре атласов сейчас нет; страница описывает порядок работ
и его причины, а не действующую сборку.

## Зачем

GPU не любит переключений. Спрайты, лежащие подряд и использующие одну текстуру, движок сливает
в один вызов отрисовки; смена текстуры сверх ~16 на батч этот вызов разбивает. Отсюда правило:
все кадры всех ролей должны жить в **одной** текстуре. Восемь отдельных PNG — восемь батчей,
один атлас с восемью кадрами — один.

Второй эффект: заливка текстуры в GPU происходит один раз при загрузке, а не при каждой
перерисовке геометрии.

Порог, за которым это начинает окупаться, у нас далеко: на десятках юнитов мелкие `Graphics`
батчатся почти как спрайты. Атлас нужен, когда появятся сотни объектов, частицы или рисунок,
который в коде не выразить.

## Формат атласа

Атлас — это пара файлов: PNG с уложенными кадрами и JSON с их координатами.

```json
{
  "frames": {
    "worker_walk_01.png": {
      "frame": { "x": 0, "y": 0, "w": 48, "h": 32 },
      "rotated": false,
      "trimmed": true,
      "spriteSourceSize": { "x": 2, "y": 4, "w": 48, "h": 32 },
      "sourceSize": { "w": 52, "h": 40 },
      "anchor": { "x": 0.5, "y": 0.5 }
    }
  },
  "animations": { "worker_walk": ["worker_walk_01.png", "worker_walk_02.png"] },
  "meta": { "image": "creatures.png", "size": { "w": 512, "h": 512 }, "scale": "1" }
}
```

- `rotated` — кадр уложен повёрнутым на 90°, парсер сам меняет местами стороны.
- `trimmed` — прозрачные поля срезаны: `sourceSize` хранит исходный размер, `spriteSourceSize` —
  положение обрезанной области внутри него.
- `animations` — именованные списки кадров, попадают в `sheet.animations`.
- `anchor` — опорная точка кадра; для вращающегося по `heading` муравья это центр `0.5/0.5`.

Загрузка одной строкой; `Assets.load` сам заберёт JSON, загрузит картинку и вызовет `parse()`:

```ts
const sheet = await Assets.load("creatures.json");
const ant = new AnimatedSprite(sheet.animations.worker_walk);
ant.animationSpeed = 0.15;
ant.anchor.set(0.5);
ant.play();
```

## Ловушки

- **`meta.scale`.** В v8 это значение напрямую задаёт resolution текстуры. Атлас, экспортированный
  как @2x, но с `"scale": "1"`, отрисуется вдвое крупнее задуманного. TexturePacker проставляет
  корректно; при ручной сборке значение нужно проверять.
- **`parse()` асинхронен.** При ручном создании `Spritesheet` обращение к `sheet.textures` до
  завершения разбора вернёт `undefined`. Через `Assets.load` этой проблемы нет.
- **Разные опорные точки кадров.** Если кадры обрезаны по-разному и `anchor` не выровнен,
  при вращении спрайт «гуляет». Опорная точка задаётся один раз для всей анимации.
- **`tint` поверх затенённого рисунка.** Тинт умножает цвет, поэтому раскрашивать одну текстуру
  под шесть ролей можно только если она нарисована белым или светло-серым. Иначе на каждую роль
  нужен свой кадр — и это снова одна текстура, просто с большим числом кадров.
- **Множественные атласы.** При `meta.related_multi_packs` загрузчик сам подтянет связанные листы,
  они доступны через `sheet.linkedSheets`.

## Три источника кадров

### Из процедурного `Graphics`

Наш случай: рисунок уже описан кодом в `packages/assets/src/creatures.ts`, а анимация задана фазой
`Math.sin(time * 15 …)`. Кадры можно **запечь** тем же кодом, не рисуя ничего заново:

1. Создать `Graphics`, вызвать `drawAnt` с нужной фазой времени.
2. Получить текстуру: `renderer.generateTexture({ target: graphics, resolution: 2 })`.
3. Извлечь пиксели: `await renderer.extract.image(texture)`.
4. Повторить для N фаз цикла и всех ролей, сложить кадры в атлас.

Плюс подхода: авторство остаётся в коде, а в рантайм едет быстрый атлас; кадры гарантированно
одинаковы по центру и пропорциям. Число кадров задаёт компромисс между плавностью и весом:
полный цикл ноги — `2π/15 ≈ 0.42` секунды, восьми кадров на цикл достаточно.

Ограничение: запекание убивает параметризацию. Полоска HP, метка груза и цвет фракции должны
либо стать отдельными кадрами, либо остаться отдельными нодами поверх спрайта.

### Из SVG

`Assets.load` для `.svg` растеризует файл в текстуру фиксированного разрешения — так уже загружается
лес в `packages/render/src/landscape.ts`. Разрешение фиксируется в момент загрузки, поэтому исходник нужно
экспортировать под максимальный размер, в котором он появится на экране. Альтернатива —
разобрать SVG в `GraphicsContext` и получить векторную геометрию вместо текстуры.

### Из растровой генерации

Порядок описан в [обзоре раздела](./index.md#генерация-графики-моделью): фон `#FF00FF`,
одна поза на кадр, вырезание фона по ключу, ручное выравнивание центров, упаковка в атлас.
Для анимации этот путь ненадёжен — кадры не совпадают между собой.

## Упаковка

Стандартный инструмент — TexturePacker: складывает кадры, срезает прозрачные поля, проставляет
`anchor` и корректный `meta.scale`, умеет экспорт в формат PixiJS. Свободные альтернативы —
`free-tex-packer`, `spritesmith`. Для суффикса `@0.5x` движок сам подберёт лист под плотность
экрана.

Практические ориентиры: держать лист в пределах 2048×2048 (гарантированный минимум для GPU,
предел `cacheAsTexture` — 4096×4096), включать обрезку полей, добавлять 1-2 px отступа между
кадрами против просачивания соседних пикселей при фильтрации.

## Где это хранить

Пока бинарных ассетов нет, отдельный пакет не нужен. Когда появятся PNG и JSON, для них
заводится `packages/assets` по правилам workspace: пакет не импортирует другие workspace-пакеты,
экспортирует по одному subpath на модуль, без корневых и barrel-экспортов.

Скрипт запекания кадров — инструмент разработки, а не часть игры: он не должен попадать
в production-сборку. Ограничение входа Vite уже задано (`build.rollupOptions.input`),
см. [лабораторию](./lab.md).
